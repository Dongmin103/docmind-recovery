# PDF text geometry recovery and native PPTX indexing

PDF blocks retain their verified page number and text when Kordoc supplies missing or out-of-page geometry. Their bounding box is omitted, and the document and affected blocks carry `PDF_GEOMETRY_OMITTED`. Chunks keep `page_num_int` for page-level search and navigation. A chunk containing any block without a reliable box has no `position_int` or `top_int`, so the preview cannot imply that all its text has exact highlight coordinates. Source hash, page count/order, block page identity, bbox page identity when supplied, and incomplete parse/OCR warnings still fail validation. Valid coordinates retain their existing behavior. The PDF geometry policy is included in the run fingerprint, even when a deployment pins the older Kordoc normalizer revision.

Set `PARSER_PLATFORM_PPTX_NATIVE_ENABLED=1` on the RAGFlow worker to select `pptx-native` for new PPTX runs. The default is `0`. Native extraction reads OOXML directly; it never calls LibreOffice or the Kordoc PPTX-to-PDF path. The parser name, version and backend are recorded as `pptx-native`, `1.1.0` and `pptx-native-offline`. Slide boundaries and the configured token budget are applied by the standard chunk path. The updated inheritance and partial-coverage policy changes the PPTX run fingerprint.

Visible non-placeholder text on the selected slide layout and master is indexed with its slide number and inherited-part locator; slide and layout visibility settings and duplicate/overridden text are respected. If readable text exists but a chart, graphic, inherited graphic, or other native structure cannot be extracted fully, the document is indexed with `PPTX_NATIVE_PARTIAL_COVERAGE` and the specific warning codes. The active source tree and registration history display `일부 내용 미추출`. A presentation with no usable native text is rejected with nonretryable `PARSER_PPTX_NATIVE_UNSUPPORTED` before parser artifacts or searchable chunks are written. Invalid or unsafe packages still fail validation. `IMAGE_OCR_NOT_RUN` is a separate informational state: image pixels have not been indexed, and the UI says `이미지 속 글자 미인식`. OCR is not enabled by this native path. Hidden content is included with explicit warnings. Source files and extracted content remain in memory during extraction; standard parser artifacts and staged chunks follow the existing cleanup and activation flow.

Before the 1.1.0 change, the approved 28-file PPTX validation set accepted 14 files and returned terminal unsupported coverage for 14. The accepted files contained 166 slides, 2,203 native blocks and 187 search chunks; aggregate parse time was 1.895 seconds and chunk time 0.065 seconds. A separate warmed extraction-plus-schema trial covered all 394 slides in 0.854 seconds. These historical local measurements do not validate the new policy or retrieval quality; decryption, image OCR, embeddings and index writes were outside the timing boundary.
