# PDF text geometry recovery and native PPTX indexing

PDF blocks retain their verified page number and text when Kordoc supplies missing or out-of-page geometry. Their bounding box is omitted, and the document and affected blocks carry `PDF_GEOMETRY_OMITTED`. Chunks keep `page_num_int` for page-level search and navigation. A chunk containing any block without a reliable box has no `position_int` or `top_int`, so the preview cannot imply that all its text has exact highlight coordinates. Source hash, page count/order, block page identity, bbox page identity when supplied, and incomplete parse/OCR warnings still fail validation. Valid coordinates retain their existing behavior. The PDF geometry policy is included in the run fingerprint, even when a deployment pins the older Kordoc normalizer revision.

Set `PARSER_PLATFORM_PPTX_NATIVE_ENABLED=1` on the RAGFlow worker to select `pptx-native` for new PPTX runs. The default is `0`. Native extraction reads OOXML directly; it never calls LibreOffice or the Kordoc PPTX-to-PDF path. The parser name, version and backend are recorded as `pptx-native`, `1.0.0` and `pptx-native-offline`. Slide boundaries and the configured token budget are applied by the standard chunk path. Switching the flag changes the PPTX run fingerprint, so queued Kordoc runs are not silently processed as native runs.

Native coverage is fail-closed. Unsupported charts/graphics, unresolved SmartArt, visible inherited master content, missing caches, and other incomplete native structures reject the run with nonretryable `PARSER_PPTX_NATIVE_UNSUPPORTED` before parser artifacts or searchable chunks are written. The extractor retains warning codes for supported but limited content. `IMAGE_OCR_NOT_RUN` means image pixels are not indexed; PPTX image OCR is disabled in this native path. Hidden content is included with explicit warnings. Source files and extracted content remain in memory during extraction; standard parser artifacts and staged chunks follow the existing cleanup and activation flow.

On the approved 28-file PPTX validation set, the production bridge and chunker accepted 14 files and returned terminal unsupported coverage for 14. The accepted files contained 166 slides, 2,203 native blocks and 187 search chunks; aggregate parse time was 1.895 seconds and chunk time 0.065 seconds. A separate warmed extraction-plus-schema trial covered all 394 slides in 0.854 seconds, including files that production correctly rejects. These are aggregate local measurements, not retrieval-quality scores or end-to-end ingestion times; decryption, image OCR, embeddings and index writes were outside the timing boundary.
