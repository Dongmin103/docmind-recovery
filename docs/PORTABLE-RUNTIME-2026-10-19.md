# Windows CPU / NVIDIA GPU 실행 패키지 검증

기존 DOCMIND 배포 코드와 검색·답변 계약을 기준으로 두 실행 패키지를 만든다.
CPU는 RAM 16GB 기준 문서 슬롯 1·파서 1·로컬 임베딩 순차 처리이며 OCR은 선택 기동한다.
GPU는 현재 배포본의 문서 슬롯 4·파서 2·임베딩 배치 32/요청 동시성 2를 유지한다.
현재 Windows 호스트의 GTE를 이미지에 포함하고 서버별 경로·키 초기화를 추가했다.

## 실행 검증

검증 장비는 Windows, RAM 16GB, WSL2/Docker Engine 29.1.3, NVIDIA GTX 1080이다.
기존 서비스와 다른 프로젝트·포트·빈 DB/볼륨에서 합성 자료만 사용했다.

| 항목 | 결과 |
|---|---|
| CPU GTE 실제 추론 | 768차원, 유한값·정규화·입력 순서·동일 입력 재현 통과 |
| GPU GTE 실제 CUDA 추론 | 같은 검증 통과, GPU 없는 경우 자동 CPU 전환 없음 |
| 새 CPU/GPU 추론 비교 | 합성 입력 3개 최소 코사인 유사도 0.9999999999979514 |
| CPU OCR | 합성 이미지 PDF 1쪽 문자 확인, GPU 레이어 0·CPU 실행 프로세스 확인 |
| GPU OCR | 같은 합성 PDF 문자 확인, GPU 레이어 99·GPU 실행/오프로딩 확인 |
| GPU 파서 설정 유지 | 8개 형식 × OCR 요청 유무, 기존 설정 지문 16개 일치 |
| 현재 배포 설정 비교 | 서비스 주소·저장 경로를 제외한 파서 설정 35개 일치 |
| 새 DB 초기화 | 모델 2종(GTE/Jina), 작업공간·논리 source 등록 및 재실행 통과 |
| CPU 웹/API | 화면 HTTP 200, 공용 세션·목록·빈 검색 code 0, 서명 없는 워커 요청 401 |
| 실제 모델 연결 | 등록된 GTE 임베딩·Jina v3.5 리랭킹 및 기존 Qwen 서버 생성 확인 |
| 답변 설정 | reviewed_v1, qwen3.8-flash-next, 문맥 32768/출력 4096 및 실제 인용 검증 |
| 회귀 검사 | 임베딩 단위 검사 12개, OCR 클라이언트/서비스 검사 16개 통과 |
| 실행 도구 | PowerShell 구문 검사, 최초 설정·기존 설치 보호·분할 파일 복원 검증 |

CPU OCR 1쪽 시험은 약 63초였다. 단일 합성 표본이며 문서 전체의 처리 속도나
서버 용량 보장으로 해석하지 않는다. GPU 동시 기동에서 발견한 NVIDIA 초기화
실패를 피하도록 OCR 준비 완료 뒤 임베딩이 시작되게 순서를 고정했다.
OCR 메모리 8GB·프로세스 256 한도도 기존 배포본에 맞췄다.
대용량 모델을 Windows 공유 경로에서 직접 읽을 때 발생한 WSL 오류를 없애기
위해 GTE와 OCR 모델은 모두 이미지에 내장해 Docker 파일시스템에서 읽는다.

## 포함 및 설치

각 ZIP에는 Docker 이미지 9종, GTE/Surya 자원, 모델 고지·라이선스, 서버 설정
예제, 초기화·시작·정상 중지 및 Windows 호스트 실행 도구가 들어간다.
파일 SHA-256·이미지 ID·소스 커밋은 패키지 manifest에 기록한다.
GitHub의 파일 크기 제한에 맞춰 분할한 파일은 버전별 parts manifest와
Join-DocMindPackage.ps1로 검증하며 하나의 ZIP으로 복원한다.

[실행 방법](../deploy/windows/README.md), [고정 모델 정보](../deploy/windows/model-manifest.json)를 따른다.
Jina 키 파일, 기존 Qwen 서버 주소, 이미 설치된 uEncryptor2 위치와 대상 서버의
원본 루트를 설정한다. 기존 서버의 키·원문·DB·색인·볼륨은 포함하지 않는다.

현재 빌드 서버의 실행 검증이며 새 서버 자체의 실행을 대신하지 않는다.
신규 서버의 실제 원본 복호화는 서버별 서명·권한·BitLocker·백업 제외 조건을
충족한 뒤 호스트 워커로 수행한다. 대상 원본과 운영 서비스는 이 검증에서 변경하지 않았다.
