# KURE 리랭커: 비상업적 연구·평가 환경

사용자가 지정한 연구 환경에서만 KURE를 선택한다. 공식 무료 프리뷰는 연구·교육·비영리용이며 영리 제품 운영은 별도 합의 대상이다. [서비스 약관](https://kure.kullm.ai/terms) · [API 계약](https://kure.kullm.ai/docs/rerank) · [계정별 한도](https://kure.kullm.ai/docs/limits)

## 설정

| 항목 | 값 |
|---|---|
| 선택 | `DOCMIND_RERANK_ID=kure-reranker-nano-20261016@kure@KURE`; 기존 설치에는 자동 적용하지 않음 |
| 자격증명 | 보호된 읽기 전용 파일 경로 `KURE_API_KEY_FILE`; 키 값은 이미지·Git에 넣지 않음 |
| 공급자 | 공식 HTTPS 엔드포인트, 고정 스냅샷. 다른 공급자로 자동 대체하지 않음 |
| 입력 | 카탈로그의 현재 파일명 최대 256자 + 줄 바꿈 + 기존 본문 앞 2,400자. 파일명이 없으면 청크 파일명, 둘 다 없으면 본문만. |
| 호출 | 검색당 최대 128청크, 순서 고정. 64개씩 전송하고 각 요청의 `top_n`은 해당 묶음 크기. `return_documents=false`. |
| 점수 | 응답의 지역 index를 원래 청크 위치에 매핑해 원점수로 정렬. 일반 검색은 배치 정규화 없음. 모델·점수·인덱스·결과 수·토큰 집계를 검증. |
| 장애 | 재평가 전체 45초. 개별 요청 최대 30초. 429/503은 제공된 대기 시간이 남은 기한 안일 때만 한 번 재시도. 부분 배치 결과를 반환하지 않음. |
| 결과 | 0.25 미만 제외(전체 파일명 일치 예외), 최고 점수 0.50 미만은 낮은 관련성 안내. 화면 8문서씩, 최대 32문서. 기존 정확한 파일명 우선·근거 중복 제거 유지. |
| 불변 | GTE 임베딩, BM25/dense 각 128, RRF k=60, 좁은 범위 후보 보충, AI 답변용 최대 16개 근거, 원본 버전·권한 조건. |

기존 연구 설치에는 [Compose 오버레이](../app/docker/docker-compose-windows-dev-kure-research.yml)로 API 서비스만 선택적으로 전환할 수 있다. 호스트 개인 키 파일 또는 Docker 비밀 관리 경로를 사용한다. 키가 잘못되거나 없으면 검색을 실패 처리한다. 롤백은 이전 API 이미지와 Compose 설정을 함께 복구한다.

## 근거

실제 자료 비교는 저장된 Jina 결과가 있는 16문항에서 동일한 후보(총 1,861개)를 사용했다. 부분 파일명 6문항에서 본문만 준 KURE의 첫 화면 정답/근거는 4/3문항, 파일명도 준 KURE는 5/4문항이었다. 같은 조건의 Jina는 각각 2/1, 5/4였다. 일반 질문 6개에서 파일명+본문은 두 모델 모두 정답/근거 5/5문항. 정답 없는 실제 자료 질문은 1개만 끝났으므로 전체 업무 오탐률을 추정할 수 없다.

별도 합성 점검에서는 80문항의 기존 후보를 동일하게 유지하고 KURE에 파일명+본문을 입력했다. 먼저 28문항으로 기준을 선택하고 52문항으로 확인했다. 기준 0.25/0.50에서 첫 화면 정답 포함은 보정 16/16, 별도 확인 28/28. 무관 질문에 결과를 반환한 경우는 각각 0/12, 0/24. 후보 이미지의 실제 부분 파일명·일반 검색 결과는 KURE 비교 기록과 일치했고, 단일 문서로 제한한 답변 근거도 범위를 지켰다. 이는 제한된 평가 결과이며 모든 질의에 대한 보장은 아니다.

원문 저장 동의 여부는 계정 소유자의 설정이다. 이 소프트웨어는 동의를 변경하지 않는다. [데이터 정책](https://kure.kullm.ai/docs/data)
