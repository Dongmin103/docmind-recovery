# DOCMIND 원문 미리보기 문서 왕복 성능 시험 — 2026-10-01

## 범위와 결과

운영 중인 로컬 DOCMIND `/docmind`의 활성 문서 10개를 대상으로 PDF·DOCX·PPTX·XLS·XLSX·HWP·HWPX를 섞어 열었다. 9개 문서를 순서대로 연 뒤 역순으로 다시 열고, 마지막에 18,354,080B HWP를 열었다. 각 요청은 복호화 전 등록부터 READY, 첫 콘텐츠 수신, 종료까지 확인했다. HWP 두 쪽 이상인 세션에서는 1→2→1쪽 이동도 확인했다. 원문 내용과 토큰은 결과 파일이나 이 문서에 기록하지 않았다.

| 측정 | 결과 |
|---|---:|
| 생성→첫 콘텐츠 성공 | 19/19, 오류 0 |
| 첫 콘텐츠 최소 / 중앙값 / p95 / 최대 | 3,796 / 5,513 / 6,254 / 6,262ms |
| HWP 쪽 이동 요청 | 10/10, 오류 0 |
| 쪽 이동 최소 / 중앙값 / 최대 | 194 / 248 / 448ms |
| 최대 HWP 표본 첫 콘텐츠 | 6,262ms |
| 최대 HWP 표본 2쪽→1쪽 | 403 / 448ms |

첫 콘텐츠 시간은 Windows 작업자의 5초 polling, 상태 조회, 복호화, API 전달을 포함한다. 브라우저의 최종 화면 그리기 시간은 아니다. p95는 19개 값의 선형 보간값을 반올림했다. 이 시험은 순차적인 닫기→재열기 왕복이며 다중 사용자 부하 시험이나 모든 문서 배치·글꼴의 검증으로 해석하지 않는다.

## 정리와 자원

19개 세션은 모두 정상 종료했고 각 HTTP 종료 응답은 200이었다. 시험 후 DB 활성 세션·공간 예약·읽기 수는 각각 0, 공유 tmpfs 사용량은 0B, Windows 임시 평문 파일과 미완료 정리 영수증도 각각 0개였다. HWP 처리 컨테이너의 설정은 CPU 0.5개, 메모리 256MiB, 프로세스·스레드 64개이며 공유 tmpfs는 별도로 128MiB다. 컨테이너 기동 이후 `memory.peak`는 165,670,912B, `oom_kill`은 0이었다. 이 peak는 이번 시험만의 최고값이 아니므로 단독 측정치로 주장하지 않는다.

## 브라우저 전환에서 발견한 문제

다른 세션이 공간을 쓰는 동안 DOCX가 `QUEUED`인 상태에서 브라우저 주소를 직접 다른 문서로 바꾸면, 기존 화면의 취소 요청이 서버에 도달하지 않아 대기 세션이 120초 만료될 때까지 남았다. 반면 DOCMIND 내부 `Back` 버튼을 누른 경우에는 즉시 `CANCELLED/COMPLETE`, 예약 0으로 정리됐다. 원인은 전체 페이지 이동 시 React 언마운트 비동기 요청에 의존한 취소 방식이다.

수정 커밋 `b14ecdc`는 `pagehide`에서 세션을 해제하고 DELETE 요청에 `keepalive`를 적용한다. 재현 회귀 시험을 먼저 실패시킨 뒤 프런트 단위 시험 11개와 변경 파일 lint를 통과했다. 실제 운영 화면에서의 적용 후 재시험 결과는 통합 배포를 마친 뒤 기록한다.
