# kordoc HWPX 시험 성능 측정

측정일: 2026-09-29. 대상: kordoc 4.15.7, HWPX 파싱 후 기존 `HwpHybridChunker` 청킹. **합성 HWPX만 측정**했으며 실제 HWP, 이미지/OCR, 암호 문서는 포함하지 않았다.

## 조건

- 호스트: AMD Ryzen 5 7600 (6코어/12스레드), RAM 16 GiB, Windows + WSL Docker.
- 파서 컨테이너: Linux amd64, 2 CPU, 메모리 2 GiB, 동시 요청 1건, `KORDOC_OFFLINE=1`, 이미지·OCR 비활성화.
- 청킹: Windows Python 프로세스에서 기존 HWP 청킹기를 사용. 시간에는 HTTP 요청, JSON 직렬화·역직렬화, 기존 청킹이 포함된다. 임베딩·검색 인덱싱은 제외한다.
- 합성 문서는 `markdownToHwpx()`로 생성했다. 본문은 서로 다른 식별자를 가진 문단, 표는 3열이다. 실제 문서의 그림·개체·복잡한 병합 셀을 대표하지 않는다.

| 입력 | 본문 문단 / 표 행 | HWPX 크기 | 파서 단독 첫 실행 | 파서 최고 RSS | HTTP 파싱 | 기존 청킹 | 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 소형 | 20 / 10 | 62 KiB | 0.029초 | 90 MiB | 0.174초 | 3.296초¹ | 3.469초 |
| 중형 | 400 / 100 | 383 KiB | 0.124초 | 140 MiB | 0.214초 | 0.333초 | 0.547초 |
| 대형 | 2,000 / 500 | 1.78 MiB | 0.289초 | 199 MiB | 0.445초 | 1.504초 | 1.949초 |
| 부하 | 10,000 / 2,000 | 7.27 MiB | 0.995초 | 488 MiB | 1.357초 | 7.816초 | 9.173초 |
| 대용량 | 30,000 / 6,000 | 21.79 MiB | 3.341초 | 804 MiB | 5.050초 | 27.293초¹ | 32.343초 |

¹ 해당 Python 프로세스의 첫 청킹이므로 라이브러리·토크나이저 초기화가 포함된다. 같은 프로세스에서 소형 문서를 다시 처리할 때는 청킹 0.024초, HTTP 파싱 0.157초, 합계 0.181초였다. 대용량 측정도 새 Python 프로세스에서 한 번 실행했다.

파서 단독 시간·RSS는 문서마다 새 2 CPU/2 GiB 컨테이너에서 측정했다. 시간은 `parse(bytes, {images:false, ocr:false})` 호출 자체를 재며, 첫 호출 수치다. RSS는 해당 Node 프로세스의 최고 상주 메모리다. HTTP 결과는 별도 2 CPU/2 GiB 서비스 컨테이너와 Windows Python 청킹 클라이언트에서 측정했다. Python 프로세스의 최고 작업 집합은 부하 문서까지 481 MiB, 대용량 단독 실행에서 661 MiB였다. 이 값은 파서 컨테이너와 별개다.

## 해석

- 큰 합성 문서에서는 **기존 청킹이 주된 지연**이다. 7.27 MiB 입력은 전체 9.17초 중 청킹 7.82초, 21.79 MiB 입력은 전체 32.34초 중 청킹 27.29초였다.
- 기존 rhwp 경로처럼 청킹기 인스턴스를 재사용하도록 시험 코드를 수정했다. 소형 반복 처리의 청킹 시간이 수정 전 0.683초에서 수정 후 0.024초로 줄었다. 첫 요청의 초기화 비용은 남는다.
- 2 GiB 파서 제한에서 21.79 MiB 합성 문서는 성공했다. **설정된 64 MiB 입력 상한에서의 메모리 안전성은 확인하지 않았다.** 실문서, 압축률이 다른 문서, OCR 활성화는 메모리와 시간을 크게 바꿀 수 있다.
- 같은 합성 문서를 기존 rhwp Python 코드로 Windows에서 측정한 참고값은 소형 0.129초, 중형 0.362초, 대형 1.662초, 부하 9.202초(각각 파싱+청킹)였다. 실행 환경과 HTTP 포함 여부가 달라 두 엔진의 우열을 판단하는 직접 비교값은 아니다.
- GPU/VRAM은 이 경로에 사용되지 않았다. OCR을 꺼 둔 CPU 파싱과 기존 청킹만 측정했다.

실제 HWP/HWPX 대표 문서가 준비되면 같은 형식·하드웨어·서비스 경로에서 처리 시간, 최고 RSS, 추출 누락, 청크 수를 다시 비교해야 한다.
