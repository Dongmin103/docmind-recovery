# 클릭 기반 임시 원본 미리보기

2026-09-28 구현. 검증 결과는 별도 검증 보고서에 기록한다.

## 처리 범위

검색과 청크 조회는 기존 색인을 사용한다. 사용자가 **원문 보기**를 선택하면
등록된 source 문서와 활성 원본 버전을 확인하고 별도 미리보기 세션을 만든다.
Windows 호스트가 원본을 임시 복호화해 전달하며, 서버 수신 확인 후 Windows
평문을 정리한다. 이 경로는 수집 작업·OCR·재청킹·색인을 생성하지 않는다.
원본과 표시 결과를 MinIO에 넣지 않는다.

| 원본 | 표시 준비 | 뷰어 |
|---|---|---|
| PDF | 바이트 전달 | 기존 PDF |
| DOCX | 바이트 전달 | 기존 Word |
| PPTX | 바이트 전달 | 기존 슬라이드 |
| XLS/XLSX | 바이트 전달 | 기존 Excel |
| DOC | DOCX로 변환 | 기존 Word |
| PPT | PPTX로 변환 | 기존 슬라이드 |
| HWP/HWPX | 선택한 페이지의 SVG 생성 | 페이지 이동·확대 |

전체 PDF 변환과 영구 원본 캐시는 사용하지 않는다. 기존 DOCX 한글 줄 간격,
Excel 정규화와 시트 탐색은 기존 뷰어가 담당한다. HWP에는 청크와 일치하는
페이지 좌표가 없으므로 정확한 위치 강조를 제공하지 않는다.

## 데이터와 실행 경계

- API는 로그인, 현재 source/문서/원본 버전, 세션 토큰을 검사한다.
  열람 토큰은 헤더로만 보내고 DB에는 해시만 기록한다.
- 현재 개발 환경의 공용 로그인은 여러 브라우저를 같은 인증 주체로 처리한다.
  세션마다 다른 토큰이 추가되지만, 이 기능이 공용 로그인을 개인 계정으로
  바꾸는 것은 아니다. 개인별 접근 정책에는 개인 로그인 구성이 필요하다.
- 처리 중인 수집 작업을 중단하지 않는다. Windows 복호화는 기존 전역 mutex를
  공유하고, 두 대기열이 모두 있을 때 미리보기 3건 다음 수집을 우선한다.
- 원본 버전 변경 시 열람을 중단한다. 원본은 같고 청크 집합만 달라졌다면
  원문을 유지하고 청크를 다시 조회하며 기존 위치 강조를 해제한다.
- 브라우저는 원본 Windows 경로나 임의 변환 경로를 지정할 수 없다.

## 초기 자원 상한

열람 세션은 전체 2개, 입력은 64MiB, 파생물은 128MiB로 제한한다.
서버 원본·파생물·변환 scratch는 하나의 **256MiB tmpfs**를 공유한다.
변환 실행부는 CPU 1개 분량, RAM 1GiB, 프로세스 128개로 제한하고 동시에
무거운 작업 하나만 처리한다. 일반 디스크로 대체 저장하지 않는다.

`preview_memory`는 Docker local volume 형식이지만 driver가 `tmpfs`이므로
일반 디스크 데이터 볼륨이 아니다. tmpfs 삭제는 메모리나 호스트 swap에 대한
복구 불가능한 소거를 보증하지 않는다. Windows 작업 공간의 암호화·백업 제외
정책도 계속 적용한다.

세션은 30초 heartbeat, 마지막 heartbeat부터 2분, 최대 60분 수명을 적용한다.
닫기·실패·만료 후 서버 파일과 브라우저 Blob URL을 해제하고, 재시도는 새로운
세션으로 원본을 다시 읽는다. 정리 실패는 완료로 숨기지 않는다.

## 개발 환경 적용

기존 네 Compose 파일과 로컬 mount를 유지하고
`app/docker/docker-compose-windows-dev-preview.yml`을 마지막에 추가한다.
이 overlay는 원본 수집·OCR·MinIO 서비스를 제거하거나 설정을 교체하지 않는다.
미리보기 실행부는 외부 포트를 공개하지 않는 전용 내부 네트워크에서 동작한다.

1. 변경된 API/DB 모델과 프런트 번들이 포함된 앱 이미지를 준비한다.
2. 미리보기 처리 이미지를 빌드하고 합성 표본 검증을 통과시킨다.
3. 기존 네 Compose + 미리보기 overlay를 `config --quiet`로 확인한다.
4. 미리보기 처리 서비스를 기동한 뒤 앱만 순차 반영한다.
5. Windows 워커의 새 미리보기 옵션을 활성화하고 승인된 범위에서 확인한다.
6. 원본 해시, 청크 집합, 정리 상태를 확인한다. 전체 소스 수집은 실행하지 않는다.

복귀 시 새 미리보기 요청을 차단하고 세션/Windows 작업의 정리를 확인한 다음
이전 앱 이미지와 워커 설정으로 돌아간다. 기존 원본/MinIO 객체를 삭제하지 않는다.
