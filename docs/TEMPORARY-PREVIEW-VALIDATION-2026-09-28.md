# 임시 원본 미리보기 검증 — 2026-09-28

최신 Office 청크 병합 기준선 `eecdbdf`에서 분리한
`feature/temporary-original-preview` 작업이다. 전체 PDF 변환을 추가하지 않았다.
구현 구조와 적용/복귀 순서는 [구현 안내](TEMPORARY-ORIGINAL-PREVIEW.md)를 따른다.

## 형식 처리 실행 시험

Linux 컨테이너를 read-only, 외부 네트워크 없음, CPU 1개 분량, RAM/swap 상한
1GiB, 임시 파일 공간 256MiB로 실행했다. DOCX/PPTX/XLSX/XLS는 생성한 한국어
합성 문서이며 DOC/PPT/PDF 시험 입력도 합성 Office 문서에서 만들었다.
시험 입력을 만드는 PDF 변환은 제품 미리보기 경로에 포함되지 않는다.

| 입력 | 결과 | 입력 크기 | 형식 처리 시간 | 컨테이너 메모리 관측 최고치 |
|---|---|---:|---:|---:|
| PDF | 원본 바이트 | 19,064B | 0.28ms | 16.34MiB |
| DOCX | 원본 바이트 | 37,023B | 0.77ms | 17.57MiB |
| PPTX | 원본 바이트 | 31,217B | 0.67ms | 17.53MiB |
| XLSX | 원본 바이트 | 6,284B | 0.39ms | 17.25MiB |
| XLS | 원본 바이트 | 5,632B | 0.20ms | 17.24MiB |
| DOC | DOCX | 22,528B | 1,110.84ms | 170.70MiB |
| PPT | PPTX | 622,080B | 1,159.53ms | 171.31MiB |

시간은 단일 작은 표본의 형식 처리만 측정했다. Windows 복호화, API 전달,
브라우저 파싱과 첫 화면 시간은 포함하지 않는다. 메모리는 cgroup의
`memory.current`를 20ms 간격으로 관측했으므로 정확한 순간 최대치를 보증하지
않는다. 시험 후 세션 디렉터리와 변환 임시파일 잔여물은 모두 0개였다.

RHWP 0.8.1은 공개 시험용 HWP/HWPX로 별도 실행했다. HWP 1쪽, HWPX 9쪽 문서의
1·2쪽을 각각 처리했으며 요청하지 않은 모든 페이지를 일괄 생성하지 않았다.
HWP 첫 페이지 0.259초, HWPX 첫 페이지 0.238초·2쪽 0.240초였다.
별도 자식 프로세스 메모리 관측은 각각 36.52MiB와 38.86MiB였다. 위 표의
전체 컨테이너 관측치와 서로 다른 지표이므로 직접 비교하지 않는다.
한컴 프로그램과의 원문 배치 일치 여부를 증명하는 시험은 아니다.

실행 중 확인하여 수정한 환경 문제:

- RHWP 네이티브 라이브러리의 FreeType 심볼 로딩: 기존 RHWP 이미지와 같은
  `LD_PRELOAD` 설정 적용.
- LibreOffice IPC가 `TMPDIR`과 별개로 `/tmp`를 요구: 이미지의 `/tmp`를 공유
  tmpfs 하위 경로에 연결. 별도 디스크나 추가 임시 메모리 공간을 만들지 않음.

## 회귀 및 통합 검증

검증 진행 중이며 최종 실행 결과를 이 절에 갱신한다. AST/단위 시험과 실제
브라우저·복호화 연동 시험의 결과는 구분해서 기록한다.

현재 개발 환경은 공용 로그인을 사용한다. 열람 세션 토큰은 분리하지만
개인별 계정/접근권한 정책이 새로 검증됐다는 의미는 아니다.
