# kordoc 추가 형식 시험 결과

2026-09-29, kordoc 4.15.7 고정. 합성 문서로 기존 독립 시험 경로를 확장했다. 운영 수집 경로와 검색 청크 활성화는 아직 연결하지 않았다.

| 형식 | 현재 시험 범위 | 기존 청커 연결 | 남은 조건 |
|---|---|---|---|
| DOCX | 문단·표 파싱, 출처 블록 ID | Word `OfficeChunker` | 실제 제목 스타일·복잡한 표·이미지 문서 비교 |
| 텍스트 PDF | 페이지·좌표가 있는 블록 파싱 | PDF `SuryaHybridChunker` | 실제 다단·표·스캔 문서 비교 |
| XLSX | 시트 제목·표 파싱 결과 비교 | 보류 | 원본 셀 주소·빈 행/열·병합 범위 보존 |

DOCX/PDF 원본에 이미지가 있으면 시험 어댑터가 거부한다. 현재 kordoc 호출에서 이미지와 OCR을 꺼 두었기 때문에 기존 OCR 결과를 잃지 않도록 한 조건이다. PDF 좌표는 kordoc의 아래쪽 기준 좌표를 기존 청커의 위쪽 기준 좌표로 변환한다.

후속 전환 준비에서 DOCX 삽입 이미지에는 kordoc `parseImage` 기반 오프라인 OCR을 연결했다. 현재 PDF 이미지 차단은 유지한다. 최신 구성과 형식별 보류 이유는 [전환 준비 문서](KORDOC-CUTOVER-READINESS-2026-09-29.md)를 따른다.

XLSX 합성 파일에는 A1/C1, A3/C3과 병합된 A5:B5가 들어 있다. kordoc 결과는 3행 2열로 압축되어 빈 B열·2/4행과 병합 범위의 원본 위치를 복원할 수 없다. 기존 Excel 청커는 실제 셀 주소로 행과 표시 HTML을 만들므로, 이 형식은 파싱 비교까지만 허용한다.

검증: kordoc Node 테스트 13개, Python HWP/Office 시험 14개 통과. DOCX와 텍스트 PDF는 합성 문서의 HTTP 파싱 → 정규화 → 기존 청킹을 끝까지 실행했고, XLSX는 청킹 단계에서 차단됨을 확인했다. 실제 업무 문서에 대한 품질·시간·메모리 결과로 해석할 수 없다. 함께 실행한 기존 rhwp 서비스 테스트 1개는 별도 시험 이미지에 `rhwp-python` 패키지가 없어 실패했다. kordoc 경로에는 이 패키지를 설치하지 않았다.

20쪽 합성 PDF에서 kordoc의 자동 머리글·바닥글 제거가 매 쪽 첫 본문 줄을 지우는 문제를 발견했다. 원본의 본문 400줄 중 380줄만 남고 `HIDDEN_TEXT_FILTERED` 경고가 반환됐다. PDF 파싱 옵션 `removeHeaderFooter: false`를 적용한 뒤 400줄과 쪽 제목이 모두 반환되는 회귀 테스트를 추가했다.

## 합성 문서 처리 시간

파서와 Python 클라이언트를 각각 2 CPU/2 GiB 컨테이너에서 실행했다. 네트워크는 외부와 차단했고 `KORDOC_OFFLINE=1`, 이미지·OCR 비활성화 상태다. HTTP 파싱에는 요청 전송, 요청마다 새 Node 작업자 시작, JSON 응답이 포함된다. 아래는 **각 문서의 첫 처리 1회 값**이다. 임베딩과 검색 인덱싱은 제외했다.

| 입력 | 구성 | HTTP 파싱 | 정규화 | 기존 청킹 | 합계 |
|---|---|---:|---:|---:|---:|
| DOCX 소형 | 문단 20개·표 10행, 37.0 kB | 0.216초 | 0.001초 | 0.236초 | 0.453초 |
| DOCX 중형 | 문단 500개·표 100행, 39.3 kB | 0.288초 | 0.008초 | 0.012초 | 0.309초 |
| 텍스트 PDF 중형 | 20쪽·본문 400줄, 14.4 kB | 0.311초 | 0.314초 | 4.117초 | 4.742초 |
| XLSX 소형 | 데이터 100행·4열, 7.1 kB | 0.175초 | — | — | 0.175초 |
| XLSX 중형 | 데이터 2,000행·4열, 48.7 kB | 0.772초 | — | — | 0.772초 |

DOCX·XLSX 값은 첫 측정의 문서별 첫 처리이고, PDF 값은 위 옵션을 고친 뒤 새 Python 프로세스에서 1회 처리한 값이다. 소형 DOCX와 중형 PDF의 청킹에는 Python 라이브러리·토크나이저 첫 로드가 포함된다. DOCX 중형은 같은 Python 프로세스에서 뒤이어 처리되어 초기화 비용이 없다. 따라서 행간의 단순 속도 비교나 실제 문서 처리량 추정에는 쓸 수 없다. 수정된 PDF 중형은 420개 구조 블록에서 본문 400줄을 모두 보존했다. XLSX 합계는 파싱까지만의 시간이다.
