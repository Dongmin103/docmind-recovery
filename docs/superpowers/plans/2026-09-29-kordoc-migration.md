# kordoc 파싱 엔진 교체 — 개략 계획

작성일: 2026-09-29. 상태: HWP/HWPX 시험 경로 구현 중, 운영 반영 전.

## 기본 방향

- 지원 형식부터 순차적으로 kordoc으로 교체한다.
- 기존 청킹 방식과 임베딩·검색 흐름을 유지한다.
- DOC/PPTX는 기존 파서를 유지한다.
- 폐쇄망에서 필요한 패키지·모델을 미리 준비한다.

## 교체 순서

| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1. 비교 기준 준비 | 대표 문서와 기존 파싱·검색 결과를 확보 | 본문, 표, 이미지, 인용 위치의 기준 |
| 2. kordoc 연결 | 별도 파서 서비스로 붙이고 기존 청킹 입력에 맞게 변환 | 폐쇄망 실행, 처리 시간, RAM 사용량 |
| 3. HWP/HWPX 우선 적용 | 일부 문서부터 교체하고 기존 HWP 청킹 코드를 재사용 | 본문·표 누락과 청킹 정책 유지 |
| 4. DOCX → PDF 확대 | DOCX 검증 후 텍스트 PDF, 스캔 PDF 순서로 적용 | 이미지 OCR, 페이지·인용 위치, 큰 문서 처리 |
| 5. XLSX 적용 | 원본 시트·셀 위치를 보존하도록 연결 | 빈 행/열, 병합 셀, 기존 행 단위 청킹 |
| 6. 운영 전환·정리 | 소량 적용 후 확대하고 불필요해진 기존 서비스 정리 | 검색 품질과 오류율, 문제 발생 시 복구 |

## 꼭 챙길 사항

- **HWP 청킹:** 현재 파서 서비스 안에 들어 있으므로 공용 코드로 분리해 그대로 재사용한다.
- **XLSX 위치:** kordoc이 빈 행·열을 압축할 수 있어 원본 셀 좌표 검증 후 전환한다. 통과하지 못하면 기존 파서를 유지한다.
- **자원:** 동시 처리 1건부터 실제 RAM·처리 시간을 측정한다. 현재 kordoc은 CPU 기준이며 보유 GPU가 자동으로 사용되지는 않는다.
- **복구:** 형식별로 전환하고, 실패한 결과가 기존 정상 검색 결과를 덮어쓰지 않게 한다.
- **폐쇄망 범위:** 이번 계획은 파서 영역이다. 외부 임베딩·리랭커까지 폐쇄망으로 옮기는 일은 별도다.

## 신구대조 기능 활용

kordoc은 `compare()`로 두 문서를 파싱해 비교하고, `diffBlocks()`로 이미 추출한 블록을 비교한다. HWP↔HWPX 비교와 표 셀 차이 확인을 지원한다.

교체 검증에서는 기존 파서와 kordoc의 출력을 같은 구조로 맞춰 차이를 확인하는 보조 도구로 활용한다. 현재 구현은 유사도 99% 이상을 변경 없음으로 취급하므로, 숫자·문장·표 값의 정확한 일치는 별도로 확인한다. 청킹·검색 품질 역시 별도로 검증한다.

사용자용 문서 버전 비교 화면은 엔진 교체 후 별도 확장 후보로 둔다. 이번 교체의 필수 개발 범위에 추가하지 않는다.

## 첫 실행 범위

**kordoc을 연결하고 HWP/HWPX 대표 문서 몇 개를 기존 결과와 비교한다.** 이 결과로 품질·리소스를 확인한 뒤 나머지 형식으로 확대한다.

진행: kordoc 4.15.7 시험 서비스와 기존 HWP 청킹 공용 모듈을 만들었다. 합성 HWPX의 파싱·표 셀 비교·청킹을 확인했다. 실제 HWP/HWPX 표본의 내용·검색 품질 비교와 수집 경로 전환은 아직 남아 있다.
