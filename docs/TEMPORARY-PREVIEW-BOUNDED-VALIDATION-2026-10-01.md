# DOCMIND 고정 자원 미리보기 검증 — 2026-10-01

## 적용 결과

코드 `d357f15`를 기존 작업 브랜치에 `67ac3b2`로 반영했다. 기존 PPTX 독립 시험 커밋은 유지했다. 앱 이미지 `docmind-ragflow:preview-bounded-20261001`(ID `a2f0fbdff400…`)과 한글 전용 `docmind-preview-processor:bounded-20261001`을 적용했다. Windows 작업자는 기존 소스·SkipRetries·3:1 순번·단일 복호화 mutex를 유지하며 `preview_enabled`만 활성화했다. DB 마이그레이션은 없다.

실행 중 수집 0건과 복호화 프로세스 부재를 확인한 뒤 기존 작업자를 멈추고 순차 적용했다. 미리보기 외 앱 환경변수 차이는 0개였다. MinIO·원본·검색 색인과 기존 파서 서비스는 변경하지 않았다.

## 확인한 동작

- Linux 회귀 테스트 52개 통과. Windows 50개 통과, POSIX 프로세스 그룹 시험 2개 제외. 프런트 10개 통과, 프로덕션 빌드 통과. Windows 작업자 자체 시험 통과.
- 한글 컨테이너를 실제 중지한 상태에서 PDF·DOCX·PPTX·XLS·XLSX를 각각 요청→직렬 복호화→전달→종료했다. 모두 성공했다.
- 실제 HWP 139개 후보에서 최소·중간·최대 크기 3개, HWPX 2개를 시험했다. HWP 최대 표본은 약 17.5MiB였다. 공개 HWP 1쪽/HWPX 9쪽 표본도 별도 제한 컨테이너에서 시험했다.
- DOCMIND `/docmind` 화면에서 DOCX와 HWP 표시를 확인했다. HWP 표·한글 글꼴, 다음 쪽→이전 쪽 재생성, 75%/100% 배율과 닫기를 확인했다. 원본 프로그램과 모든 픽셀의 일치를 검증한 것은 아니다.
- 한글 1건이 96MiB를 예약한 상태에서 동시 6건 중 5건 대기·1건 `PREVIEW_QUEUE_FULL`. 취소→재등록, heartbeat 중에도 120초 만료, 한글 종료 후 다음 PDF 진행을 확인했다. 대기 세션의 예약·평문은 0이었다.
- DOC 실문서는 복호화 전에 415 `PREVIEW_FORMAT_UNSUPPORTED`; DOC/PPT 양쪽은 API·화면 단위 시험에서도 거절한다.
- 한글 준비 후 처리 컨테이너를 중지하고 미생성 페이지를 요청했다. 해당 세션이 `FAILED/PREVIEW_PROCESSOR_FAILED`로 끝나고 예약·읽기 수가 0으로 정리됐다. 처리 컨테이너는 복구했다.
- 별도 동일 제한 컨테이너에서 렌더러 메모리 초과를 주입했다. cgroup `oom_kill=1`, 추가 swap 0, `PREVIEW_PROCESS_FAILED` 반환과 임시파일 0을 확인했다. 실제 운영 문서의 OOM을 유발한 시험은 아니다.
- 입력 64MiB·SVG 16MiB 초과, child timeout/취소, 권한/원본 변경, 다운로드 획득 중 취소를 회귀 시험으로 검증했다.
- 마지막 전체 DB 검사에서 활성 세션·예약·읽기 수 0, 서버 tmpfs 사용 0B, Windows 평문 0개·대기 정리 영수증 0개였다. 미리보기 코드에는 객체 저장소 호출이 없고 검증일 storage audit 신규 기록도 0개였다.

## 시간 측정

아래 첫 바이트 시간은 요청부터 READY·첫 콘텐츠 수신까지이며 5초 Windows polling과 상태 조회 간격을 포함한다. 화면 렌더링 시간과 구분한다. 복호화·전송은 Windows 작업자 단조 시계 기록이며 전송에는 API 검증·ACK 왕복을 포함한다.

| 형식/표본 | 복호화 ms | 전송·ACK ms | 호스트 정리 ms | 요청→첫 콘텐츠 ms |
|---|---:|---:|---:|---:|
| PDF | 57.5 | 45.3 | 18.4 | 2985 |
| DOCX | 63.2 | 59.8 | 19.2 | 5141 |
| PPTX | 59.3 | 48.7 | 19.2 | 5469 |
| XLS | 60.2 | 41.8 | 19.1 | 5453 |
| XLSX | 61.1 | 47.7 | 19.5 | 5031 |
| HWP 15.5KiB | 56.4 | 31.1 | 19.2 | 7500 |
| HWP 46.5KiB | 58.3 | 35.2 | 21.3 | 2188 |
| HWP 17923.9KiB | 205.4 | 152.2 | 24.1 | 10391 |
| HWPX | 75.8 | 39.0 | 22.6 | 2969 |
| HWPX | 58.0 | 30.0 | 19.8 | 5453 |

- 상태 관측에서 일반 형식의 큐·획득 대기는 대체로 약 2.5~4.9초였다. 이는 5초 작업자 polling 정책을 유지한 결과이며 복호화 시간 자체는 약 57~63ms였다. 상태 관측값은 조회 간격만큼 오차가 있다.
- 공개 표본의 순수 처리: HWP 첫 쪽 685ms; HWPX 첫 쪽 407ms, 다음 쪽 347ms, 제거된 쪽 재생성 365ms.
- 실제 한글 첫 콘텐츠: 약 2.2~10.4초. 17.5MiB HWP의 페이지 이동은 1484ms/500ms였다.
- 브라우저 HWP 첫 화면은 클릭 후 12.5초 이내에 관측했다. 도구 호출 사이 관측 간격이 포함된 상한값으로 정확한 렌더 완료 시각은 아니다. 브라우저 다음 쪽 934ms, 제거된 이전 쪽 재생성 358ms를 관측했다.

## 기동·복귀

현재 배포의 비공개 스냅샷과 스크립트는 `C:/DocMindDev/docmind/.local/preview-bounded-20261001`에 있다. 환경변수·작업자 설정을 포함하므로 디렉터리 전체를 공유하거나 커밋하지 않는다.

- `Start-Preview.ps1`: 수집 유휴 확인 → 기존 Compose 순서와 환경 유지 → 한글 서비스 → 앱 → 기존 단일 작업자 기동. 이미 동작 중인 작업자를 추가로 띄우지 않는다.
- `Rollback-Preview.ps1`: 대상 앱 ID·수집 유휴·열린 미리보기/예약 없음·Windows 평문 없음을 먼저 확인한다. 원문을 모두 닫고 신규 열람을 중단한 유지보수 시점에 사용한다. 이전 앱 이미지와 미리보기 비활성 설정으로 복귀하며 원본·색인은 삭제하지 않는다. 후속 앱 배포가 있으면 거절한다.
- `deployment.json`, `compose-args.json`, `preserve-runtime.json`, `release.json`과 이전 앱/작업자 설정을 보관했다. 재기동은 이 Compose 목록을 사용한다. 후속 배포는 `release.json`의 앱 이미지도 갱신해야 이전 이미지로 되돌아가지 않는다.
- 두 PowerShell 스크립트의 구문을 검사했다. 복귀 스크립트는 현재 정상 서비스에 실제 실행하지 않았다.

Windows PowerShell 5를 현재 PowerShell 7 환경에서 직접 자식으로 띄울 때 Security 모듈 형식 충돌이 있어, 검증된 PowerShell 7 실행 경로를 기동 설정에 기록했다. 수집 옵션과 복호화 실행 파일은 동일하다. 작업자 로그는 기존 UTF-16 인코딩으로 명시해 기록한다.

## 표본 한계

대형 HWP는 실제 17.5MiB 표본까지 확인했다. 실제 HWPX는 2개(각 1쪽), 공개 HWPX는 9쪽이다. 모든 문서 배치·폰트 조합을 보장하지 않는다. 자원 상한은 올리지 않았으며 초과 입력은 해당 미리보기만 실패하도록 처리한다.
