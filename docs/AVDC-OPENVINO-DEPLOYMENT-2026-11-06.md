# AVDC OpenVINO 운영 전환 및 Git 동기화

2026-11-06 14:58 KST에 AVDC 임베딩을 **OpenVINO FP32**로 전환했고 15:03 KST에
검증을 마쳤다. 이전 [66.684초 구성](AVDC-DEPLOYMENT-2026-11-05.md)의 자원·동시성은
유지했다. 15:15 KST 이후 Git 반영 점검에서도 실제 서비스·풀 소스 해시와 영구
Compose 설정이 일치했고 8개 서비스가 실행 중이었다. 이번 Git 반영은 재배포가 아니다.

## 실제 적용한 구성

| 항목 | 최대 허용량 / 설정 |
|---|---|
| 호스트 | Xeon Gold 5220R 2개, 물리 48코어 / 논리 프로세서 96개 |
| DocMind VM | 96 vCPU, 상한 100%, 고정 RAM 64 GiB |
| 임베딩 | OpenVINO 2026.4.1, FP32, 22작업자 × 4스레드, 작업자별 1 stream |
| 임베딩 자원 | 논리 프로세서 88개분 한도, VM CPU 0-47·56-95, 메모리 52 GiB |
| 파서 | 2작업자, 합산 CPU 4개분 한도, 메모리 1 GiB, OCR 비활성 |
| 나머지 서비스 | VM CPU 48-55 공유; API 2.5 GiB, ES 1.5 GiB |
| 문서 / 임베딩 요청 동시성 | 12 / 24 |
| 내부 배치 | 128토큰 이하 최대 16개, 긴 입력 1개, 최소 token fill 85% |

한도는 실제 평균 사용량이나 CPU 칩 개수가 아니다. VM CPU 영역 분리는 물리
코어를 독점 예약하는 것도 아니다. 모델·토크나이저·청킹·검색·KURE는 바꾸지 않았다.

`tools/avdc_embedding/service.py`, `pool.py`는 운영 파일과 바이트 단위로 일치한다.
CPU 설정 예제, 오프라인 이미지 확장 Dockerfile, 실제 모델 변환 스크립트도 포함한다.
실제 비밀 설정·키·모델 가중치·원문·청크·벡터는 Git에 포함하지 않는다.
Windows GPU용 `tools/local_embedding` 경로는 별개로 유지한다.

## 적용 검증

- 임베딩 컨테이너만 교체했고 다른 7개 컨테이너 ID는 유지됐다.
- 영구 Compose 두 파일을 대조했고 이미지·서비스 해시 및 모든 자원 한도가 일치했다.
- 기존 동일 source의 질문 12개에서 문서 순서·대표/보조 근거·관련성 상태 12/12 동일.
- 등록 작업 535건·문서 레코드 535건·문서별 청크 수 합계 43,501개는 적용 전후 동일.
  **535건을 새로 처리한 것이 아니다.** 이전 시험 등록을 포함한 DB 현황이다.
- 배포 중 색인·재색인 0회, 활성 파싱·복호화 작업 0건.
- 검색 검증 전후 호스트 CPU 평균 6.75%, 관측 최대 14%; 임베딩 메모리 최대
  21.85 GiB, 전체 컨테이너 합계 최대 25.14 GiB.
- 그룹웨어 Running, HTTP 12/12 정상, 평균 13.08 ms·p95 18.23 ms.
  호스트 12표본/62.81초, VM 90표본/89.25초이며 색인 부하 시험 수치가 아니다.
  컨테이너 메모리는 캐시를 포함한 cgroup 값이다.

## 기존 동일 24입력 시험

| 항목 | 기존 PyTorch CPU | OpenVINO CPU | 기존 PC GPU |
|---|---:|---:|---:|
| 전체 색인 시간 | 70.159초 | 61.697초 | 39.191초 |
| 호스트 CPU 평균 / 관측 최대 | 28.64% / 78% | 34.20% / 87% | 다른 장비 |
| 전체 컨테이너 최대 메모리 | 41.92 GiB | 31.78 GiB | 다른 장비 |
| 그룹웨어 HTTP 평균 / p95 | 19.93 / 35.99 ms | 14.63 / 25.81 ms | 해당 없음 |

24개 중 22개 성공(242쪽·1,359청크), 동일한 OCR 필요 문서 2개 제외.
첫 DB 작업 등록부터 마지막 검색 활성화까지로 복호화·전송을 포함한다. 서비스
준비/예열과 최종 정리 확인은 경계 밖이다. 임시 평문 정리·원본 해시도 별도 검증했다.
CPU는 같은 계측 조건에서 12.06% 단축. GPU 대비 22.506초 더 걸리는 1.57배이며,
장비와 동시성이 다른 전체 시스템 비교다. 66.684초는 이전 비계측 시험 기록이므로
70.159초와 같은 기준의 값으로 섞지 않는다. 모두 예열된 단회 결과다.

청크 내용·토큰·위치·순서가 동일했고 1,359개 벡터 비교의 최대 절대 오차는
1.63624e-6였다. 이전 새 source 비교에서 근거가 달라진 1건은 키워드 검색의
샤드별 통계와 동점 후보 순서로 재현됐다. 의미 검색 상위 128개는 동일했고,
전역 통계와 안정된 동점 정렬을 쓰는 진단에서 키워드 상위 128개도 일치했다.
이 진단 변경을 운영 검색 알고리즘에 적용한 것은 아니다. 배포 후 동일 source
12질문의 회귀 통과가 모든 문서의 검색 정확도 100%를 뜻하지 않는다.

## 복구 및 재현 범위

운영 배포 경로는 `/opt/docmind-avdc/.local/deploy-openvino-20261106/`.
수동 `rollback.sh`와 이전 Compose 사본은 유지하고 임시 자동 복구 타이머는 해제했다.
소스·모델 해시, 이미지 ID, 버전, 비밀값 없는 확인 결과는
[JSON 기록](measurements/avdc-openvino-deployment-2026-11-06.json)에 있다.
모델 가중치와 기존 CPU 기반 이미지는 별도 보관해야 한다. Git만으로 실제
인증키·운영 데이터까지 복원할 수 있는 전체 설치 백업이라고 해석하지 않는다.

Git 점검에서 이전 AVDC 병렬 실행 코드·시험 기록 10개 커밋도 원격 main에 없음을
확인했다. 이번 동기화에는 그 이력과 위 운영 소스/설정 예제/배포 기록을 함께 포함한다.

## Git 반영 전 검사

- OpenVINO 배포 소스 해시·배치 순서·토큰 제한·FP32/스레드 설정·인증·CPU 영역: 8건 통과.
- 기존 로컬 임베딩 단위 검사: 13건 통과. 이 경로의 미커밋 CPU 실험 수정 2개 파일은
  이번 반영 대상에서 제외하고 그대로 보존했다. AVDC 운영 소스는 위 별도 경로에 있다.
- 병렬 실행부·작업 claim 경계: 20건 통과. DB 부트스트랩 없는 격리 검사다.
- Kordoc HTTP 클라이언트: 9건 통과. 실제 클라이언트 모듈을 앱 전체 초기화 없이 검사했다.
- Kordoc 서버 2/4작업자·초과 요청·실패 격리: 로컬 임시 컨테이너에서 7건 통과.
- Windows 12슬롯 경로 격리·공유 복호화 게이트·자식 종료 검사 통과.
- Compose 예제 구문 검사와 제품 경로의 제거 대상 런타임 참조 검사 통과.
- 원격 AVDC에는 읽기 전용 확인만 수행했다. 위 검사는 운영 문서를 처리하지 않았다.
